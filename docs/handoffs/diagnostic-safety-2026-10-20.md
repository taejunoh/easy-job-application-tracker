# 공개 인계: 로컬 진단 안전 유틸리티

상태: 공개용 로컬 유틸리티와 오프라인 테스트를 PR #13으로 main에 병합했습니다(merge commit `0453935`). 별도 배포 작업과 외부 재현은 하지 않았습니다. PR을 열 때 저장소의 Vercel 연동이 미리보기 배포를 자동으로 만들었습니다.

이 패키지는 의존성 없는 유틸리티, 명시적으로 실행하는 Node 오프라인 테스트, 이 인계 문서로만 구성됩니다. 유틸리티는 종결 상태가 확인된 빈 환경 인벤토리 검증, 캡처 대기 중 오류·취소 처리와 자원 정리, 출력 스트림 오류의 sticky 처리, 이미 취소된 입력 작업의 시작 방지를 제공합니다. 출력 오류를 안전하게 처리하는 것은 출력 내용의 비밀정보 제거를 뜻하지 않습니다. 모듈은 import 시 파일·네트워크·자격 증명·외부 서비스에 접근하지 않습니다.

공개 오프라인 테스트는 48/48 통과했습니다(Node 22.22.2에서 실행, 저장소 engines `>=22.22.2 <23`). 비공개 prototype의 과거 테스트 60/60 결과는 별도 테스트 묶음의 기록이며, 이 공개 테스트 결과와 혼동하면 안 됩니다. 앱 전체 Jest는 PR #13 CI의 `verify` 잡(run 39532425797, Node 22.22.2, Linux x64)에서 `npm run test:ci`로 통과했습니다. 테스트 묶음은 100개 통과·4개 skip(총 104개), 테스트는 2,836개 통과·23개 skip(총 2,859개)였고 약 790초 걸렸습니다. 같은 잡의 lint, typecheck, build도 통과했습니다. 이는 CI 환경의 결과입니다. 과거 로컬 기준 실행에서는 4,096건 초과 reconciliation 테스트가 timeout됐고 후속 전체 테스트도 120초 제한에 걸려 Jest 요약 없이 끝났는데, 이 로컬 timeout의 원인은 진단하지 않았고 CI 통과로 해소됐다고 보지 않습니다. 앱 전체 테스트는 로컬에서 다시 실행하지 않았습니다.

이번 보강에서는 개행 감지(문자열·CR 포함), `timeoutMs`를 포함한 인자의 SCHEMA 검증, 설정 실패 시 raw 오류나 listener가 새지 않도록 하는 처리, 어떤 정리 단계가 실패해도 항상 settle되도록 하는 finish, 비동기 emit 거부의 격리, `onFailure` listener 보호, 이미 종료·오류 상태인 입력의 즉시 실패, 위조된 AbortSignal의 SCHEMA 처리, 인벤토리 검사 중 getter 오류의 ISOLATION 변환을 추가하고 각각 테스트했습니다. `npm run test:diagnostic-safety`로 실행할 수 있습니다. 호환성을 위해 `signal: null`은 signal 없음으로, 유한한 실수 `timeoutMs`는 허용합니다. 알려진 잔여 한계: `onFailure`가 listener를 등록한 뒤 예외를 던지면 그 listener는 sticky output에 남지만, 이미 settle된 뒤 호출되므로 동작에는 영향이 없습니다. 입력 대기가 끝난 뒤 입력 스트림에 발생하는 `error` 처리는 호출자 책임입니다.

외부 재현은 수행하지 않았고 근본 원인은 확인되지 않았습니다. 운영 앱 변경이나 보안 보고서 작성도 이 작업 범위에 포함되지 않았습니다. 이 공개 유틸리티는 비공개/live helper에 연결되지 않았습니다.

## 안전한 후속 작업

Claude는 공개 유틸리티와 오프라인 테스트만 로컬에서 검토하고, 필요하면 이 범위의 테스트를 다시 실행할 수 있습니다. 앱 테스트 기준 실패는 요청이 별도로 있을 때 독립적으로 진단합니다. 비공개 prototype에서 남은 M1 reconciliation 이벤트 의미와 M2 readiness deadline 검토는 이 패키지에서 해결하거나 수정한 것으로 간주하지 않습니다. 외부 재현을 재개하거나 중단된 안전 경계를 우회하는 용도로 이 인계를 사용하지 마세요.

오프라인 테스트 실행:

```sh
npm run test:diagnostic-safety
# 또는
node --test scripts/lib/diagnostic-safety.node-test.mjs
```

이 `.node-test.mjs` 파일은 저장소 Jest 설정의 `**/__tests__/**/*.test.ts` 패턴에 포함되지 않고 CI에도 연결돼 있지 않으므로 명령을 명시해 실행합니다. 이 결과만으로 앱 전체 테스트 상태를 판단할 수 없습니다.
